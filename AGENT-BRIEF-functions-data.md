## 2. Demo-reliability spine in `shared.js` (do this first — everything else builds on it)

Edit `functions/lib/shared.js`, then run `node functions/scripts/sync_shared.js`.

### 2a. `DEMO_DATA_MODE` + snapshot layer
Add a snapshot helper every Function wraps its live path in:

- `isDemoMode()` → `truthy(process.env.DEMO_DATA_MODE)` (accept `"1"`, `"true"`, `"on"`).
- `loadSnapshot(fnName, key)` → read `functions/demo_data/<fnName>.<key>.json`. Return parsed body
  or `null` if absent. (Snapshots store the Function's **output body**, i.e. the object inside `ok()`.)
- `snapshotKey(args)` → deterministic key from the significant args, e.g.
  `` `${lat.toFixed(4)}_${lng.toFixed(4)}_${radius_m}_${day||''}_${time||hour||''}` ``. Keep a single
  canonical key builder so freeze + read agree.
- `withData(fnName, args, liveFn)` — the wrapper each Function uses:
  1. If `isDemoMode()`: return `loadSnapshot(fnName, snapshotKey(args))`; if the snapshot is missing,
     **fall through to `liveFn()`** (demo should still work if a snapshot wasn't frozen — never 404
     the demo). Log a warning so freeze coverage gaps are visible.
  2. Else (live mode): `try { return await liveFn(); } catch (e) { const snap =
     loadSnapshot(fnName, snapshotKey(args)); if (snap) { console.error('degraded to snapshot:', e.message);
     return snap; } throw e; }` — **this is the fail-fast degrade**: a live miss falls back to the
     frozen snapshot instead of surfacing an error.

> Note: `functions/demo_data/` is a **repo-root-of-functions shared dir**. Because DO bundles each
> function directory independently, each Function that reads snapshots needs the demo_data files
> available at bundle time. **Recommended:** keep the canonical `functions/demo_data/`, and have
> `sync_shared.js` (extend it) copy `demo_data/` into each function dir as `./demo_data/` alongside
> the synced `shared.js`. `loadSnapshot` reads `path.join(__dirname, 'demo_data', ...)`. Update
> `.gitignore`/`project.yml` as needed so the per-function copies aren't double-committed if you
> prefer .gitignoring them (then the sync script is a required predeploy step — document it in DEPLOY.md).

### 2b. Fail-fast fetch profile
`fetchJSON` currently defaults `timeoutMs: 8000, retries: 2`. Add a **demo profile** without breaking
the live defaults:
- Add `demoFetchOpts()` → `{ timeoutMs: 2500, retries: 0 }` when
  `isDemoMode() || truthy(process.env.DEMO_FAILFAST)`, else `{}`.
- In each Function's live fetch calls, spread it last: `fetchJSON(url, { headers, ...baseOpts, ...demoFetchOpts() })`.
  Net effect: on the demo build a live miss aborts in ~2.5s and degrades to snapshot (§2a step 2),
  never ~20s of retries. Verify this in §7.

### 2c. Exports
Add `isDemoMode, loadSnapshot, snapshotKey, withData, demoFetchOpts, truthy` to `module.exports`.
Re-run `sync_shared.js`. Confirm all six existing functions still run via `invoke_local.js`.

### 4e. Deterministic score (code does math, never the LLM)
Per candidate at the chosen window, compute:
1. **Hard constraints (any failure ⇒ `eliminated:true`, keep it in output but unranked):**
   - inside an active closure (`get_closures` geometry contains/near the point),
   - `check_clearance.allowed === false` (collect the failing `checks` into `violations[]`),
   - spot occupied per schedule (`get_vendors` shows a same-spot `scheduled_here` vendor in the window),
   - travel time > `max_travel_minutes`.
2. **Demand score (0..1):** `get_foot_traffic.score` + restaurant-density term (from
   `get_restaurants.saturation`/`window.saturation`) + event-proximity bonus (from `get_events`,
   scaled by distance + `expected_attendance`). Document the weights as named constants.
3. **Competition penalty (0..1):** from §4d `overlap_score` (menu items + price tier), **not** a
   cuisine label alone.
4. `score = clamp(demand - competition_penalty, 0, 1)` (define weights as constants;
   keep it simple and explainable). Produce a full `breakdown`.
